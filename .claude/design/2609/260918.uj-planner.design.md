# 디자인 의뢰: U.J planner

갤럭시 Z 플립7 전용 **주간 자동 배치 플래너** 안드로이드 앱의 UI를 디자인해 주세요.
구현은 Jetpack Compose + Material 3로 하며, 받은 결과물을 그대로 코드로 옮길 예정입니다.

## 1. 이 앱이 푸는 문제

사용자는 플래너를 자주 쓰지만 **"언제 할지"를 정하는 걸 못 합니다.** 할 일이 뭔지는 아는데,
그걸 주간 시간표 어디에 넣을지 결정하는 데서 막힙니다.

그래서 이 앱은 일정을 둘로 나눕니다.

| | 사용자가 정하는 것 | 앱이 정하는 것 |
|---|---|---|
| **고정 일정** | 요일 + 시각 + 소요시간 (매주 반복) | 없음 |
| **가변 일정** | 소요시간, 주당 횟수, 우선순위, 선호 시간대, 마감 요일 | **언제 할지** |

가변 일정 예: `운동 / 1시간 / 주 3회 / 우선순위 높음 / 저녁 / 마감 없음`
→ 앱이 고정 일정을 피해 이번 주 빈 시간 세 곳에 알아서 넣습니다.

못 한 일정은 앱을 열 때 확인받고, 이번 주 남은 빈칸에 다시 넣습니다.

**사용자는 한 명, 본인입니다.** 계정·로그인·공유·서버가 없습니다. 매일 여러 번 짧게 여는 도구입니다.

## 2. 디자인이 전달해야 할 느낌

- **"내가 짠 게 아니라 짜여 있다"** 는 안도감. 열었을 때 할 일이 이미 자리에 놓여 있어야 합니다.
- 고정 일정은 **배경(움직이지 않는 것)**, 가변 일정은 **전경(앱이 놓아 준 것)** 으로 한눈에 구분돼야 합니다.
- 못 한 일정을 다룰 때 **죄책감을 주지 않습니다.** "놓쳤다"가 아니라 "다시 넣어 줄게"의 톤입니다.
- 꾸밈보다 밀도와 가독성. 장식용 일러스트는 필요 없습니다.

## 3. 기기와 화면 크기 — 세 가지 상태를 모두 디자인합니다

| 상태 | 크기 (dp) | 쓰임 |
|---|---|---|
| **메인 (펼침)** | 411 × 960, 세로로 매우 긴 21:9 | 주간 시간표 보기·편집 |
| **플렉스 (90°로 반 접어 세움)** | 위 411 × 480 / 아래 411 × 480 | 책상에 세워 두고 오늘 일정 확인 |
| **커버 (접음)** | 399 × 361, 거의 정사각형 | 폰을 안 펴고 한 손으로 완료 체크 |

제약:
- **플렉스 모드**: 화면 정중앙에 가로 힌지가 지나갑니다. 접히는 선 위에 글자나 버튼을 걸치지 마세요. 위쪽은 보는 영역, 아래쪽은 누르는 영역입니다.
- **커버 화면**: 모서리에 카메라 컷아웃이 있으니 네 모서리에는 핵심 요소를 두지 마세요. 엄지 하나로 조작하므로 버튼은 크게, 정보는 최소로.
- 터치 타겟은 모든 화면에서 최소 48dp.
- 메인 화면은 세로로 길어 상단이 엄지에 안 닿습니다. 자주 누르는 것은 아래쪽에 둡니다.

## 4. 디자인할 화면

### 4-1. 주간 그리드 (메인 · 앱의 기본 화면)
- 월~일 7열 × 30분 단위 행의 타임그리드. 표시 범위는 보통 08:00~24:00.
- 고정 일정 = 중립색(회색 계열) 블록. 가변 일정 = 색이 있는 블록.
- 가변 일정 블록의 상태 4가지를 구분해 주세요: **예정 / 완료 / 못함 / 버림**
- 오늘 열과 현재 시각 표시.
- **배치 실패 배너**: 빈 시간이 모자라 못 넣은 가변 일정이 있으면 상단에 드러냅니다. 조용히 숨기면 안 되는 정보입니다. 탭하면 어떤 일정이 몇 회 못 들어갔는지 보입니다.
- 블록을 길게 눌러 다른 칸으로 옮길 수 있습니다 (옮기는 중의 모습도 필요).
- 일정 추가 진입점, 설정 진입점.

> **풀어 주셨으면 하는 문제**: 폭 411dp에 시간축을 빼고 7열을 넣으면 한 열이 약 50dp입니다.
> 블록 안에 일정 이름이 거의 안 들어갑니다. 7일을 한눈에 보는 것이 이 앱의 핵심이라 열을 줄이고
> 싶지는 않습니다. 색·약어·탭 시 상세 등으로 이 밀도 문제를 어떻게 풀지 제안해 주세요.
> 더 나은 구조가 있다면 대안도 환영합니다.

### 4-2. 일정 등록 / 편집 (메인)
- **고정 / 가변** 탭 전환.
- 고정: 이름, 요일(복수 선택), 시작 시각, 소요시간.
- 가변: 이름, 소요시간, 주당 횟수(1~7), 우선순위(3단계), 선호 시간대(아침/오후/저녁/아무때나), 마감 요일(없음 포함), 색.
- 입력이 5~6개라 폼이 길어집니다. 타이핑을 줄이고 탭으로 고르게 해 주세요 (칩, 스테퍼, 세그먼트 등).
- 삭제 동작.

### 4-3. 밀린 일정 시트 (메인 · 앱을 열 때 자동으로 뜨는 바텀시트)
- 시간이 지났는데 체크 안 된 일정 목록.
- 항목마다 버튼 3개: **했음 / 못함 / 버림**
  - 했음 → 완료 처리
  - 못함 → 이번 주 남은 빈칸에 다시 배치
  - 버림 → 이번 주는 포기
- 여러 개를 빠르게 처리할 수 있어야 합니다. 매일 보는 화면이라 피곤하면 안 됩니다.
- 재배치 결과 피드백: "목 19:00로 옮겼어요" 같은 확인.
- 빈칸이 없을 때 뜨는 확인 다이얼로그: "이번 주 전체를 다시 짤까요?"

### 4-4. 설정 (메인)
- 요일별 **배치 가능 시간대** (요일 7개 각각 시작~종료). 예: 평일 08:00–24:00, 주말 10:00–01:00.
- 평일/주말 일괄 적용 같은 단축 동작이 있으면 좋습니다.
- "이번 주 다시 짜기" 버튼.

### 4-5. 커버 화면 (399 × 361)
- 카드 하나: **지금 할 일** (없으면 다음 할 일과 남은 시간).
- 큰 **완료** 버튼 하나. 보조로 **못함**.
- 오늘 남은 일정 개수 정도의 최소 정보.
- 네비게이션이 없는 단일 화면입니다.

### 4-6. 플렉스 모드 (위 480 / 아래 480)
- 위: 오늘 타임라인 (세로 목록, 현재 시각 기준).
- 아래: 지금 할 일 + 완료/못함 버튼, 밀린 일정이 있으면 그 처리.

### 4-7. 상태별 변형
- **빈 상태**: 처음 열어서 일정이 하나도 없을 때. 고정 일정부터 넣도록 안내.
- **배치 실패 있음**, **밀린 일정 있음**, **오늘 할 일 다 끝남** (커버·플렉스 포함).

## 5. 시각 규칙

- **Material 3** 기반. Compose `ColorScheme` / `Typography` 에 그대로 매핑될 수 있게 설계해 주세요.
- **라이트·다크 모두.** 커버 화면은 AMOLED 특성상 다크가 기본이어도 좋습니다.
- 가변 일정용 **일정 색 팔레트 8색 내외**. 50dp 폭 블록에서도 서로 구분되고, 라이트·다크 양쪽에서 글자 대비(WCAG AA)를 만족해야 합니다.
- 상태 표현은 색에만 의존하지 말고 아이콘·질감·취소선 등을 병행해 주세요.
- 폰트는 시스템 기본(한글 포함)을 전제로 합니다. 별도 폰트를 쓰려면 이유를 적어 주세요.
- UI 문구는 **한국어**, 짧은 구어체 ("했음", "못함", "다시 짜기").

## 6. 하지 않는 것

알림·푸시, 구글 캘린더 연동, 로그인·계정·동기화, 월간/일간 뷰, 홈 위젯, 온보딩 튜토리얼, 통계·리포트 화면.
요청하지 않은 화면은 추가하지 마세요.

## 7. 받고 싶은 결과물

1. **디자인 방향** 1~2안 — 색·무드·밀도를 보여 주는 주간 그리드 한 장씩. 방향을 고른 뒤 나머지를 진행합니다.
2. **화면 목업** — 4장의 모든 화면, 세 가지 기기 상태, 라이트·다크.
3. **디자인 토큰**
   - 색: Material 3 role 이름(`primary`, `surface`, `surfaceVariant`, `error` …)에 매핑한 hex 값, 라이트·다크 각각
   - 일정 색 팔레트: 색마다 배경·글자 hex 쌍
   - 타이포: Material 3 type scale 기준 크기·굵기
   - 간격·모서리 반경·그리드 행 높이·열 폭
4. **컴포넌트 스펙** — 일정 블록(고정 / 가변 × 상태 4종 / 드래그 중), 배치 실패 배너, 밀린 일정 항목, 커버 카드, 가변 일정 입력 컨트롤.
5. 4-1의 **밀도 문제에 대한 제안**과 그 근거.

수치는 전부 **dp / sp** 로 적어 주세요. 코드로 바로 옮깁니다.
