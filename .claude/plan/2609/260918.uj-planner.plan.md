# Plan: U.J planner — 주간 자동 배치 플래너

**Source PRD**: `.claude/prd/2609/260918.uj-planner.prd.md`
**Selected Milestone**: v1 전체 (PRD 완료 기준 1~5)
**Complexity**: Medium
**Application ID**: `com.uj.planner`
**표시 이름**: U.J planner

## Summary

고정 일정만 사람이 넣고 가변 일정은 앱이 남는 시간에 배치하는 주간 플래너.
배치 로직을 안드로이드 의존성 없는 순수 Kotlin으로 떼어내 JUnit으로 검증하고,
그 위에 Room 영속화와 Compose UI를 얹는다. 폴더블 대응은 표현 계층 문제라 마지막에 붙인다.

## Patterns to Mirror

레포가 비어 있어 **미러링할 기존 코드가 없다.** 아래는 이 프로젝트가 처음 정하는 기준이며,
Phase 1 이후 모든 코드가 여기에 맞춘다.

| 범주 | 기준 | 근거 |
|---|---|---|
| 시각 표현 | 자정 기준 분(`Int`) | `LocalTime` Room 컨버터를 안 만들어도 되고, 슬롯 산술이 뺄셈으로 끝난다 |
| 날짜 표현 | `LocalDate` ↔ `epochDay: Long` 컨버터 1개 | 컨버터를 하나로 묶어 둔다 |
| 요일 | `java.time.DayOfWeek.value` (월=1 … 일=7) | 주 시작이 월요일이라 그대로 정렬 키가 된다 |
| 실패 표현 | 배치 실패는 `ScheduleResult.unplaced` 로 **반환**한다. 예외를 던지거나 조용히 버리지 않는다 | PRD 배치 규칙 7 |
| 테스트 | `app/src/test/` 에 순수 JUnit. 계측 테스트 없음 | 스케줄러가 안드로이드에 의존하지 않으므로 계측이 필요 없다 |
| DI | 프레임워크 없이 `Application` 에서 직접 조립 | 1인용 앱에 Hilt는 과하다. 생성자 주입만 지킨다 |

## Tasks

### Phase 0 — 골격과 툴체인 증명

#### Task 0.1: Gradle 프로젝트 생성
- **Action**: 버전 카탈로그 기반 단일 모듈(`app`) 생성. compileSdk 36 / targetSdk 36 / minSdk 30, JVM target 17.
- **Mirror**: 없음(최초). AGP·Kotlin·KSP 버전은 서로 짝이 맞는 조합으로 고정하고 카탈로그에 한 번만 적는다.
- **Validate**: `./gradlew :app:assembleDebug`

#### Task 0.2: 빈 Compose 화면 띄우고 에뮬레이터 설치
- **Action**: "안녕" 한 줄짜리 Composable 하나. Manifest에 `android:resizeableActivity="true"`.
- **Validate**: `./tools/emu.sh start && ./gradlew :app:installDebug` 후 화면 확인
- **의도**: 로직을 쓰기 전에 **JDK→Gradle→SDK→에뮬레이터 경로 전체를 먼저 증명**한다. 이 단계에서 깨지면 원인이 하나뿐이다.

### Phase 1 — 배치 알고리즘 (핵심)

#### Task 1.1: 도메인 모델 정의
- **Action**: `FixedBlock(dayOfWeek, startMin, durationMin)`, `FlexTaskSpec(id, durationMin, timesPerWeek, priority, window, deadlineDay?)`, `Slot(dayOfWeek, startMin, endMin)`, `PlannedSlot`, `ScheduleResult(planned, unplaced)`. 안드로이드 import 금지.
- **Validate**: `./gradlew :app:compileDebugKotlin`

#### Task 1.2: 스케줄러 구현
- **Action**: PRD 배치 규칙 1~7 그대로.
  1. 요일별 가용시간에서 고정 일정과 이미 확정된 배치를 뺀 빈 슬롯 목록을 만든다 (30분 단위).
  2. 가변 일정 정렬: 마감 오름차순(없으면 뒤) → 우선순위 내림차순 → 소요시간 내림차순.
  3. 각 일정의 필요 횟수만큼, **선호 시간대 안에서** first-fit.
  4. 못 넣은 건 2차 패스에서 시간대 제약을 풀고 재시도.
  5. 같은 일정은 하루 1회까지.
  6. 끝내 못 넣으면 `unplaced` 에 담아 반환.
- **Mirror**: 실패는 반환값으로. `ponytail:` 주석으로 그리디 first-fit임을 명시하고 교체 조건을 적는다.
- **Validate**: `./gradlew :app:testDebugUnitTest`

#### Task 1.3: SchedulerTest 작성 ★
- **Action**: 순수 JUnit. 최소 커버 항목:
  - 빈 주에 가변 일정 1개(주 3회) → 서로 다른 3일에 배치
  - 고정 일정이 막은 시간대는 피한다
  - 선호 시간대(저녁) 안에만 들어간다
  - 선호 시간대가 꽉 차면 2차 패스로 다른 시간대에 들어간다
  - 자리가 아예 없으면 `unplaced` 에 담기고 예외가 안 난다
  - 마감이 빠른 일정이 먼저 자리를 잡는다
- **Validate**: `./gradlew :app:testDebugUnitTest`
- **의도**: 이 앱에서 틀리면 제일 아픈 게 배치 로직이다. 검증은 여기 하나로 족하다.

### Phase 2 — 영속화

#### Task 2.1: Room 엔티티·DAO·DB
- **Action**: `FixedEventEntity`, `FlexTaskEntity`, `PlacementEntity`, `DayAvailabilityEntity`. 컨버터는 `LocalDate ↔ epochDay` 하나와 enum 2개.
- **Validate**: `./gradlew :app:assembleDebug` (KSP 생성 성공)

#### Task 2.2: Repository
- **Action**: DAO를 묶고, "주간 재계산"과 "미완료 재배치" 두 진입점만 노출. 스케줄러는 여기서만 호출한다.
- **Validate**: `./gradlew :app:testDebugUnitTest`

### Phase 3 — 주 화면

#### Task 3.1: 주간 그리드
- **Action**: 7열 × 30분 행. 고정=회색, 가변=색상. 상단에 `unplaced` 배너.
- **Validate**: 에뮬레이터 육안 확인

#### Task 3.2: 일정 등록/편집
- **Action**: 고정/가변 탭. 가변 입력은 소요시간·주당 횟수·우선순위·선호 시간대·마감 요일 5개.
- **Validate**: 등록 → 그리드에 반영되는지 확인

### Phase 4 — 재배정

#### Task 4.1: 밀린 일정 시트
- **Action**: 앱 진입 시 `status=PLANNED && 종료시각 < now` 수집 → 바텀시트. 항목당 `했음`/`못함`/`버림`.
- **Validate**: 에뮬레이터 시간을 앞으로 돌려 확인

#### Task 4.2: 재배치와 전체 재계산
- **Action**: `못함`만 이번 주 남은 빈칸에 first-fit. 빈칸이 없으면 "주 전체를 다시 짤까?" 확인 후 `DONE` 고정하고 재계산.
- **Validate**: 빈칸 없는 상황을 만들어 확인 다이얼로그가 뜨는지

### Phase 5 — 설정

#### Task 5.1: 요일별 가용 시간
- **Action**: 요일 7개 각각 시작/종료 시각. 기본값 평일 08:00–24:00, 주말 10:00–25:00(다음날 01:00).
- **Validate**: 값 변경 → 재계산 시 반영

### Phase 6 — 폴더블 대응

#### Task 6.1: AdaptiveHost
- **Action**: `WindowInfoTracker` 로 `FoldingFeature` 구독. 분기 세 갈래.
  - 화면 폭·높이 모두 Compact (커버, 약 399×361dp) → `CoverScreen`
  - `HALF_OPENED` + `HORIZONTAL` → 위=오늘 타임라인 / 아래=퀵 액션
  - 그 외 → `WeekGridScreen`
- **Validate**: `./tools/emu.sh flex`, `./tools/emu.sh cover`

#### Task 6.2: 커버 화면
- **Action**: 지금/다음 할 일 카드 1개 + 완료 체크 버튼 1개. 터치 타겟 최소 48dp.
- **Validate**: `./tools/emu.sh cover` 로 1048×948 강제 후 확인

## Validation

```bash
# 스케줄러 (필수 — 이게 깨지면 앱이 틀린 것)
./gradlew :app:testDebugUnitTest

# 빌드
./gradlew :app:assembleDebug

# 에뮬레이터에 설치하고 실행
./tools/emu.sh start
./gradlew :app:installDebug

# 폴더블 상태 전환
./tools/emu.sh flex    # 반 접기
./tools/emu.sh cover   # 커버 크기(1048x948) 강제
./tools/emu.sh main    # 복구
```

레포에 `Makefile` 이 없으므로 위 Gradle 명령이 이 프로젝트의 검증 명령이다.

## Risks

| 위험 | 가능성 | 완화 |
|---|---|---|
| AGP·Kotlin·KSP 버전 불일치로 첫 빌드 실패 | 높음 | 카탈로그에 검증된 조합 하나만 고정. Phase 0에서 먼저 터뜨려 본다 |
| 첫 Gradle 빌드가 의존성 받느라 오래 걸림 | 높음 | 예상된 비용. Phase 0에 몰아 둔다 |
| 커버 디스플레이 에뮬레이션 미동작 | **확정** | 이미 확인됨. `emu.sh cover` 의 `wm size` 우회로 대체. `emu.sh` 에 한계 명시 |
| 그리디 배치가 사람 눈에 어색한 결과를 냄 | 중간 | 어색한 케이스를 테스트로 고정한 뒤 정렬 기준만 손본다. 솔버 도입은 마지막 수단 |
| 주말 가용시간이 자정을 넘어감(25:00) | 중간 | 분 단위 정수로 다루므로 1500분처럼 24시 초과를 그대로 표현. 날짜 경계는 배치 시점에만 환산 |
| `resizeableActivity` 누락 시 접힘 전환에서 액티비티 재생성 | 낮음 | Phase 0 Manifest에 처음부터 넣는다 |
