## Summary

고정 일정만 사람이 넣고 가변 일정은 앱이 남는 시간에 배치하는 주간 플래너.
배치 로직을 안드로이드 의존성 없는 순수 Kotlin으로 떼어내 JUnit으로 검증하고,
그 위에 Room 영속화와 Compose UI를 얹는다. 폴더블 대응은 표현 계층 문제라 마지막에 붙인다.

## 아키텍처

### 모듈 — 2개

```
uj-planner/
├── domain/     Kotlin JVM 모듈. 안드로이드 의존성 0
└── app/        안드로이드 모듈. domain 에 의존
```

`app → domain` 단방향이고 반대는 없다. **Gradle이 강제한다** — `domain` 은 안드로이드 플러그인을
적용하지 않으므로 `import android.*` 가 컴파일 자체가 안 된다. 규율을 사람이 지키는 게 아니라
빌드가 막는다. 스케줄러 테스트도 안드로이드 없이 돌아서 빠르다.

| | `domain` 에 둔다 | `domain` 에 두지 않는다 |
|---|---|---|
| | 배치 규칙과 그 입출력 타입 | Room 엔티티, Compose, `Context`, `LiveData` |

### 패키지 — 레이어별

```
domain/src/main/kotlin/com/uj/planner/domain/
├── model/
│   ├── FixedBlock.kt          요일 + 시작분 + 소요분
│   ├── FlexTaskSpec.kt        소요분·주당횟수·우선순위·선호시간대·마감요일
│   ├── Window.kt              enum MORNING / AFTERNOON / EVENING / ANY
│   ├── Slot.kt                요일 + 시작분 + 종료분
│   └── ScheduleResult.kt      planned + unplaced
├── Scheduler.kt               fun schedule(ScheduleInput): ScheduleResult
└── WeekMath.kt                주 시작일·절단점·남은 횟수 (순수 계산)

app/src/main/kotlin/com/uj/planner/
├── PlannerApp.kt              Application — 의존성 수동 조립
├── data/
│   ├── entity/                FixedEvent / FlexTask / Placement / DayAvailability
│   ├── dao/
│   ├── Converters.kt          LocalDate ↔ epochDay (enum 은 Room 이 직접 저장)
│   ├── PlannerDatabase.kt
│   └── PlannerRepository.kt
└── ui/
    ├── AdaptiveHost.kt        커버 / 플렉스 / 메인 분기
    ├── week/                  WeekGridScreen + WeekViewModel
    ├── edit/                  TaskEditScreen + TaskEditViewModel
    ├── settings/              SettingsScreen + SettingsViewModel
    ├── missed/                MissedSheet
    ├── cover/                 CoverScreen
    └── theme/
```

화면이 5개뿐이라 레이어별이 찾기 쉽다. 기능별로 가르면 테이블 4개를 여러 화면이 공유해서
`data` 가 어디 속하는지 애매해진다.

### 데이터 흐름 — 단방향

```
Room DAO (Flow) → Repository → ViewModel (StateFlow) → Composable
        ▲                                                    │
        └──────────────────── 사용자 액션 ────────────────────┘
```

Room이 `Flow` 를 주므로 별도 갱신 로직이 필요 없다. 쓰기가 일어나면 화면이 알아서 따라온다.

**`Scheduler` 는 `Repository` 만 호출한다.** ViewModel도 Composable도 스케줄러를 직접 부르지 않는다.
배치가 일어나는 지점을 하나로 묶어야 "언제 시간표가 바뀌는가"를 추적할 수 있다.

Repository가 밖으로 여는 진입점은 둘뿐이다.

| 진입점 | 언제 |
|---|---|
| `recomputeWeek(weekStart)` | 가변 일정·고정 일정·가용시간이 바뀌었을 때 |
| `resolveMissed(decisions)` | 밀린 일정 시트에서 `했음`/`못함`/`버림` 을 누른 뒤 |

### 배치 결과는 저장한다

조회할 때마다 계산하지 않고 `Placement` 테이블에 **써 둔다.** PRD가 "재배치할 때 이미 짜인
가변 일정은 건드리지 않는다"를 요구하므로, 기존 배치가 남아 있어야 그걸 피해서 채울 수 있다.
매번 계산하면 볼 때마다 시간표가 달라진다.

### 화면 분기

```
AdaptiveHost
├── 폭·높이 모두 Compact (커버, 약 399×361dp)  → CoverScreen        (네비게이션 없음)
├── FoldingFeature HALF_OPENED + HORIZONTAL    → 위/아래 분할
└── 그 외                                       → NavHost
                                                    ├── week  (시작)
                                                    ├── edit/{id?}
                                                    └── settings
```

`MissedSheet` 는 목적지가 아니라 `week` 위에 뜨는 바텀시트다.
커버 화면은 네비게이션 스택을 갖지 않는다 — 카드 하나와 버튼 하나가 전부다.

### 의존성

| 넣는 것 | 이유 |
|---|---|
| Compose BOM + Material3 | UI |
| navigation-compose | 목적지 3개의 뒤로가기 스택 |
| room-runtime / room-ktx + KSP | 영속화 |
| androidx.window | `FoldingFeature` |
| lifecycle-viewmodel-compose | 접힘 시 configuration change 대응 |

**넣지 않는 것**: Hilt(1인용 앱에 과하다 — `Application` 에서 직접 조립), Retrofit·이미지 로더(네트워크가 없다).


## Patterns to Mirror

레포가 비어 있어 **미러링할 기존 코드가 없다.** 아래는 이 프로젝트가 처음 정하는 기준이며,
Phase 1 이후 모든 코드가 여기에 맞춘다.

| 범주 | 기준 | 근거 |
|---|---|---|
| 시각 표현 | 자정 기준 분(`Int`) | `LocalTime` Room 컨버터를 안 만들어도 되고, 슬롯 산술이 뺄셈으로 끝난다 |
| 날짜 표현 | `LocalDate` ↔ `epochDay: Long` 컨버터 1개 | 컨버터를 하나로 묶어 둔다 |
| 요일 | `java.time.DayOfWeek.value` (월=1 … 일=7) | 주 시작이 월요일이라 그대로 정렬 키가 된다 |
| 실패 표현 | 배치 실패는 `ScheduleResult.unplaced` 로 **반환**한다. 예외를 던지거나 조용히 버리지 않는다 | PRD 배치 규칙 7 |
| 테스트 | `app/src/test/` 에 순수 JUnit. 계측 테스트 없음 | 스케줄러가 안드로이드에 의존하지 않으므로 계측이 필요 없다 |
| DI | 프레임워크 없이 `Application` 에서 직접 조립 | 1인용 앱에 Hilt는 과하다. 생성자 주입만 지킨다 |

## Tasks

### Phase 0 — 골격과 툴체인 증명

#### Task 0.1: Gradle 2모듈 골격 생성
- **Action**: 버전 카탈로그 기반으로 `:app`(안드로이드)과 `:domain`(Kotlin JVM) 두 모듈 생성.
  compileSdk 37 / targetSdk 36 / minSdk 30, JVM target 17. `:app` 이 `:domain` 에 의존한다.
- **Mirror**: 없음(최초). AGP·Kotlin·KSP 버전은 서로 짝이 맞는 조합으로 고정하고 카탈로그에 한 번만 적는다.
- **Validate**: `./gradlew :app:assembleDebug :domain:build`

#### Task 0.1b: 모듈 경계 확인
- **Action**: `:domain` 에서 `import android.content.Context` 를 한 줄 넣어 **컴파일이 실패하는지** 확인하고 지운다.
- **의도**: 경계가 규율이 아니라 빌드로 강제되는지 여기서 한 번 증명한다. 실패하지 않으면 `domain/build.gradle.kts` 가 잘못된 것이다.
- **Validate**: `./gradlew :domain:compileKotlin` 이 실패 → 줄 삭제 후 성공

#### Task 0.2: 빈 Compose 화면 띄우고 에뮬레이터 설치
- **Action**: "안녕" 한 줄짜리 Composable 하나. Manifest에 `android:resizeableActivity="true"`.
- **Validate**: `./tools/emu.sh start && ./gradlew :app:installDebug` 후 화면 확인
- **의도**: 로직을 쓰기 전에 **JDK→Gradle→SDK→에뮬레이터 경로 전체를 먼저 증명**한다. 이 단계에서 깨지면 원인이 하나뿐이다.

### Phase 1 — 배치 알고리즘 (핵심)

#### Task 1.1: 도메인 모델 정의
- **Action**: `:domain` 모듈에 정의한다. `FixedBlock(dayOfWeek, startMin, durationMin)`, `FlexTaskSpec(id, durationMin, timesPerWeek, priority, window, deadlineDay?)`, `Slot(dayOfWeek, startMin, endMin)`, `PlannedSlot`, `ScheduleResult(planned, unplaced)`. 안드로이드 import 금지.
- **Validate**: `./gradlew :domain:compileKotlin`

#### Task 1.2: 스케줄러 구현 (`:domain`)
- **Action**: PRD 배치 규칙 1~7 그대로.
  1. 요일별 가용시간에서 고정 일정과 이미 확정된 배치를 뺀 빈 슬롯 목록을 만든다 (30분 단위).
  2. 가변 일정 정렬: 마감 오름차순(없으면 뒤) → 우선순위 내림차순 → 소요시간 내림차순.
  3. 각 일정의 필요 횟수만큼, **선호 시간대 안에서** first-fit.
  4. 못 넣은 건 2차 패스에서 시간대 제약을 풀고 재시도.
  5. 같은 일정은 하루 1회까지.
  6. 끝내 못 넣으면 `unplaced` 에 담아 반환.
- **Mirror**: 실패는 반환값으로. `ponytail:` 주석으로 그리디 first-fit임을 명시하고 교체 조건을 적는다.
- **Validate**: `./gradlew :app:testDebugUnitTest`

#### Task 1.3: SchedulerTest 작성 ★
- **Action**: 순수 JUnit. 최소 커버 항목:
  - 빈 주에 가변 일정 1개(주 3회) → 서로 다른 3일에 배치
  - 고정 일정이 막은 시간대는 피한다
  - 선호 시간대(저녁) 안에만 들어간다
  - 선호 시간대가 꽉 차면 2차 패스로 다른 시간대에 들어간다
  - 자리가 아예 없으면 `unplaced` 에 담기고 예외가 안 난다
  - 마감이 빠른 일정이 먼저 자리를 잡는다
- **Validate**: `./gradlew :domain:test`
- **의도**: 이 앱에서 틀리면 제일 아픈 게 배치 로직이다. 검증은 여기 하나로 족하다.

### Phase 7 — 데이터 내보내기·가져오기

서버가 없고 자동 백업도 꺼 두어서(`allowBackup=false`) 데이터가 폰 안에만 있다. 앱을 지우거나 폰을 바꾸면 복구할 길이 없으므로
설정 화면에서 DB 파일 하나를 통째로 내보내고 가져온다. JSON 같은 별도 형식은 만들지 않는다 — 파일 복사가 가장 적은 코드로 가장 정확하다.

#### Task 7.1: 백업 (`data/Backup.kt`)
- **내보내기**: `VACUUM INTO` 로 캐시에 일관된 사본을 만든 뒤 사용자가 고른 위치(SAF `CreateDocument`)로 복사. 파일명 `uj-planner-YYYYMMDD.db`
- **가져오기**: 고른 파일(SAF `OpenDocument`)을 DB 폴더에 받아 검증 → DB 닫기 → `-wal`/`-shm` 삭제 → rename 으로 교체 → 앱 재시작
- **검증**: SQLite 헤더, `PRAGMA quick_check`, `user_version` 과 Room `identity_hash` 가 지금 DB 와 같을 것. 다르면 아무것도 바꾸지 않고 이유를 알린다
- 크기 상한 50MB (1년 치가 수백 KB 다)
- **Validate**: 에뮬레이터에서 내보내기 → 일정 삭제 → 가져오기 → 일정 복구 확인. 아무 파일이나 골랐을 때 거부되고 데이터가 그대로인지 확인

#### Task 7.2: 설정 화면
- "데이터" 구역: 설명 + `내보내기` / `가져오기` 알약 버튼. 가져오기는 파일을 고른 뒤 "지금 데이터가 모두 바뀐다"는 확인 다이얼로그를 거친다
- 가용 시간 저장이 도는 중에는 가져오기를 막는다 (DB 를 닫기 때문)

## Risks

| 위험 | 가능성 | 완화 |
|---|---|---|
| AGP·Kotlin·KSP 버전 불일치로 첫 빌드 실패 | 높음 | 카탈로그에 검증된 조합 하나만 고정. Phase 0에서 먼저 터뜨려 본다 |
| 첫 Gradle 빌드가 의존성 받느라 오래 걸림 | 높음 | 예상된 비용. Phase 0에 몰아 둔다 |
| 커버 디스플레이 에뮬레이션 미동작 | **확정** | 이미 확인됨. `emu.sh cover` 의 `wm size` 우회로 대체. `emu.sh` 에 한계 명시 |
| 그리디 배치가 사람 눈에 어색한 결과를 냄 | 중간 | 어색한 케이스를 테스트로 고정한 뒤 정렬 기준만 손본다. 솔버 도입은 마지막 수단 |
| 주말 가용시간이 자정을 넘어감(25:00) | 중간 | 분 단위 정수로 다루므로 1500분처럼 24시 초과를 그대로 표현. 날짜 경계는 배치 시점에만 환산 |
| `resizeableActivity` 누락 시 접힘 전환에서 액티비티 재생성 | 낮음 | Phase 0 Manifest에 처음부터 넣는다 |
