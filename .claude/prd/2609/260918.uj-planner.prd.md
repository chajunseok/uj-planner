# U.J planner — 주간 자동 배치 플래너

## 문제

플래너를 자주 쓰지만 일정을 짜는 것 자체를 못 한다. "언제 할지" 정하는 데서 막힌다.
할 일이 뭔지는 아는데, 그걸 주간 시간표 어디에 넣을지 결정하는 비용이 크다.

## 해결

주 단위로 **고정 일정**만 내가 넣고, **가변 일정**은 조건만 적어두면 앱이 남는 시간에 알아서 배치한다.
못 한 일정은 앱을 열 때 확인받고 남은 빈칸에 다시 넣는다.

## 사용자

나 한 명. 갤럭시 Z 플립7. 로컬 전용, 계정 없음.

---

## 핵심 개념

| | 내가 정하는 것 | 앱이 정하는 것 |
|---|---|---|
| **고정 일정** | 요일 + 시각 + 소요시간 | 없음 (그대로 둠) |
| **가변 일정** | 소요시간, 주당 횟수, 우선순위, 선호 시간대, 마감 요일 | **언제 할지** |

가변 일정 예시: `운동 / 1시간 / 주 3회 / 우선순위 높음 / 저녁 / 마감 없음`

---

## 배치 규칙

1. 요일별 **가용 시간대**(설정에서 요일마다 따로 지정)에서 시작한다.
2. 가용 시간 − 고정 일정 − 이미 확정된 배치 = **빈칸**.
3. 가변 일정 정렬: **마감 빠른 순 → 우선순위 높은 순 → 소요시간 긴 순**.
4. 순서대로, 주당 횟수만큼, **선호 시간대 안에서** 앞에서부터 채운다(first-fit).
5. 선호 시간대에 자리가 없으면 2차 패스에서 시간대 제약을 풀고 다시 시도한다.
6. 같은 가변 일정은 **하루에 한 번만**. 주 3회면 서로 다른 3일.
7. 끝까지 못 넣은 건 **"배치 실패" 목록으로 화면에 보여준다.** 조용히 버리지 않는다.

> 제약 솔버가 아니라 그리디 first-fit. 주 단위 슬롯이 수십 개 수준이라 이걸로 충분하다.
> 체감 품질이 떨어지면 그때 교체한다.

## 재배정 규칙

- **트리거**: 앱을 열 때. 종료 시각이 지났는데 체크 안 된 일정을 모아 시트로 띄운다.
- **선택지**: `했음`(완료) / `못함`(재배치 대상) / `버림`(이번 주 포기).
- **재배치**: `못함`만, **이번 주 남은 빈칸에** first-fit. 이미 짜인 다른 가변 일정은 건드리지 않는다.
- **빈칸이 없으면**: "주 전체를 다시 짤까?" 확인 → 예를 누르면 완료된 일정은 고정한 채 나머지를 전부 재계산.

## 전제 (물어보지 않고 정한 것)

- 주 시작은 **월요일**.
- 배치 단위는 **30분 슬롯**.
- 고정 일정은 **매주 반복**. 이번 주만 있는 일정은 v1에 없음.
- 데이터는 Room, 기기 로컬에만.
- Kotlin + Jetpack Compose, 에뮬레이터(폴더블 AVD)로 개발.

## 완료 기준

1. 고정 일정 몇 개와 가변 일정 몇 개를 넣으면 주간 그리드가 자동으로 채워진다.
2. 지난 일정을 `못함`으로 찍으면 이번 주 다른 빈칸으로 옮겨간다.
3. 배치 못 한 일정이 화면에 드러난다.
4. 앱을 껐다 켜도 남아 있다.
5. 접었을 때 커버에서 다음 할 일이 보이고 체크된다.
